# AGENTS.md

Guidance for coding agents working in this repository.

## What this is

`ethlo r7` is a JVM HTTP gateway (Java 25, Undertow/XNIO) that routes and filters requests and
audits them into memory-mapped binary journals. Pre-release. Docs source lives in `docs/`
(published to https://r7.ethlo.com); `docs/config.md`, `docs/extensibility.md` and
`docs/journaling.md` are the user-facing contracts and should be updated when behaviour changes.

## Build and test

```bash
./mvnw clean install                      # full build (flatc runs in generate-sources)
./mvnw -q -DskipTests install              # what the benchmark suite expects first
./mvnw test -pl r7-journal-mmap            # one module
./mvnw test -pl r7-core -Dtest=RedactingHeadersTest             # one test class
./mvnw test -pl r7-journal-mmap -Dtest=JournalIntegrityTest#recoveryReportsOnlyTheContentItCouldNotRead
./mvnw package -DskipTests -pl r7-undertow,r7-tailer-jsonld -am  # what CI builds for images
```

- `r7-journal-mmap` runs `bin/flatc` (checked into the repo) over
  `src/main/flatbuffers/journal.fbs` at `generate-sources`. Editing the `.fbs` regenerates the
  Java tables under `target/generated-sources/flatbuffers` — never hand-edit those.
- Filters and predicates are registered by `@AutoService`, which needs annotation processing
  enabled (configured in `r7-core/pom.xml`). A new factory that does not show up in YAML is
  almost always a missing `@AutoService` or a build that skipped processing.
- `r7-core` surefire runs with `workingDirectory = src/test/resources`; relative paths in those
  tests resolve there.
- `*BenchmarkTest` / `*PerformanceTest` classes run as part of the normal test phase and are
  timing-sensitive — treat their failures as noise only after re-running.

## Running

```bash
java -jar r7-undertow/target/r7-undertow-1.0-SNAPSHOT.jar        # reads ./config/{routes,server}.yaml
R7_ROUTES_CONFIG=... R7_SERVER_CONFIG=... java -jar ...          # override config paths
docker compose up -d                                             # nginx test backend on :11111
./build.sh          # mvn install + paketo buildpack image (r7-gateway)
./build-native.sh   # GraalVM native image via Dockerfile.native
```

Recommended JVM flags (used by benchmarks, docs and CI images):
`-XX:+UseZGC --enable-native-access=ALL-UNNAMED --sun-misc-unsafe-memory-access=allow`.

Data plane defaults to `:8888`, management/status/dashboard to `:18888`.

Integration tests in `r7-undertow` pick their target via `-Dr7.test.mode=in-process` (default),
`jvm-docker` or `native-docker`; the Docker modes need locally built `r7-gateway` / `r7-gateway-native` images.

Benchmarks live in `benchmark/` (`./run.sh --quick`); read `benchmark/README.md` before quoting
any number — only the `vs r7` (passthrough-relative) deltas are meaningful, and `--repeat 3`
is the minimum for believing a small difference.

`docs/schemas/latest.yaml` (consumed by the Monaco editor in `r7-editor/`) is generated by
running `com.ethlo.r7.schema.JsonSchemaGenerator` from the repo root; it writes that path
directly. Regenerate it after adding or changing any filter/predicate config record.

## Module layout and dependency direction

```
r7-api          contracts only: GatewayExchange/Request/Response, Headers, the filter interfaces
r7-utils        allocation-conscious containers (PackedGatewayHeaders, FastGatewayHeaders, …)
r7-core         the engine: YAML config model, route registry, built-in filters/predicates, SPI
r7-journal-api  Journal, JournalExchange, JournalLevel, integrity listeners
r7-journal-mmap the r7f format: writer, decoder, recovery, reassembler, R7Tailer
r7-undertow     the entrypoint: R7Main, R7UndertowHandler, status/dashboard, DTOs
r7-tailer-jsonld sidecar apps that turn journals into JSON / ClickHouse rows
```

`api` is the contract and `core` the engine; keep the separation strict — `r7-api` must not
depend on the engine, and nothing in the request path should reach into `r7-undertow` types.
`r7-editor` (Vite + Monaco) and `benchmark/` are not Maven modules.

## Request lifecycle

`R7UndertowHandler.handleRequest` is the hot path, and the ordering it implements is specified in
`docs/config.md` §3:

1. global request filters → 2. route predicates in declaration order, first match wins (404 if
none) → 3. route request filters → 4. upstream proxy → 5. route response filters → 6. global
response filters → 7. async journal dispatch.

Things that are load-bearing here:

- Filters are declared in one flat list and are **phase-aware** by which interface they
  implement (`ClientRequestGatewayFilter`, `UpstreamRequestGatewayFilter`,
  `ClientResponseGatewayFilter`, `CompletedGatewayFilter`). Response-phase filters are
  registered during the request phase and executed on the way out, onion-style.
- Rejecting a request means `exchange.shortCircuit(...)`, never an exception. A thrown exception
  is a runtime failure: the pipeline **fails closed**, skips remaining filters and returns 500.
- `ClientRequestGatewayFilter.requiresDispatch()` returning true moves execution onto a virtual
  thread. Anything blocking (I/O, DB) must declare it or it stalls an XNIO I/O thread.
- `exchange.attributes()` is for telemetry/journaling only; functional state between filters goes
  through typed `StateKey` attachments.
- Config is hot-reloadable (`HotReloadService`); stateful filters (rate limiter buckets, circuit
  breakers) reset on reload by design.

## Configuration model

`config/routes.yaml` + optional `config/server.yaml`, Jackson 3 (`tools.jackson`) YAML with
`SNAKE_CASE` naming and `FAIL_ON_UNKNOWN_PROPERTIES`. Config records are Java records
implementing `ValidatableConfig`; defaults are expressed as overridden accessors returning
`Optional.ofNullable(field).orElse(default)` (see `ServerConfig`), and `validate(...)` builds
nested error paths via `result.nested("...")`.

Validation is fail-fast at startup and is expected to *name the offending field* rather than let
a constructor throw a stack trace later — `ServerConfig.StorageConfig` is the worked example
(shard count must be a power of two, shard size bounded by `R7fJournalProvider` constants).
When adding a constraint that a lower layer already enforces, mirror it here with a message that
tells the operator which value to use, and derive the bounds from that layer's constants so the
two cannot drift.

`${VAR:default}` interpolation happens before type conversion (`EnvInterpolator`); a missing
variable with no default fails validation. Header matching is case-insensitive throughout.

## Journaling — read the specs before touching it

This is the most intricate part of the system and it has its own written specifications. Read
them before changing anything in `r7-journal-mmap` or `ShardedJournalWriter`/`StatefulJournal`:

- `r7-journal-mmap/FORMAT.md` — the r7f on-disk format: 1024-byte preamble, big-endian framing,
  seal record, `RETAIN` flag, `.flux` → `.r7f` lifecycle. Payloads are FlatBuffers
  (little-endian) per `src/main/flatbuffers/journal.fbs`.
- `r7-journal-mmap/README.md` — write-path semantics, no-fsync durability model, backpressure,
  and `ExchangeReassembler`/`ReassemblyOptions` tuning and consumer-callback contract.
- `design/journal-invariants.md` — the four invariants and the test names that enforce each. If
  a change touches recovery, deletion, checkpointing or eviction, find the invariant it belongs
  to and the named test, and extend that test.

The rules most easily broken by a well-intentioned local fix:

- **The magic is the commit.** Entry magic and seal magic are written *last*, behind a
  store-store fence. Zero where a magic belongs means "no committed entry".
- **A reader must either advance or prove end-of-data**, on every exit path including the loop
  condition; and it must never advance without delivering. A consumer that throws is *refusing*
  the record — rewind and stall, do not skip. Counters increment after the callback, not before.
- **Deletion requires proof.** "Scan found no records" is not proof; quarantine instead.
  Decisions one component makes about bytes another cannot see must travel in the file.
- **Observer callbacks are not part of the work** — a throw from an integrity listener must not
  be mistakable for a damaged segment.
- Journal text (header names/values, attributes, start lines) is **ISO-8859-1**. Values set
  programmatically are validated at the point of mutation and rejected with
  `InvalidTextValueException`; do not move that check into the journal writer.
- The gateway writes binary only. Conversion to JSON/ClickHouse belongs to the sidecar tailers,
  never the request path.

Journal levels are `NONE | METADATA | HEADERS | FULL`, per route and per direction.

## Performance constraints

Targets: 100k+ req/s, p99 under 1ms, 8KB buffers (L1/L2 friendly). Concretely this means:

- No allocation in the hot path; no object-graph construction during ingestion. Prefer the
  existing packed/array-backed containers in `r7-utils` over `Map`/`List`.
- Off-heap primary: `MappedByteBuffer` for journal segments, `DirectByteBuffer` for
  socket-to-journal transfers. Bodies are streamed and teed, never buffered wholesale.
- Journals are sharded by `requestId` hash (power-of-two shard count) to avoid lock contention.
- Any change claimed as a performance improvement needs a `benchmark/run.sh --repeat 3` run
  behind it, with `environment.txt` alongside the number.

## Style

Allman braces, `final` on parameters and locals, records for config and DTOs, explicit `this.`
in config accessors — follow the surrounding file, and `.editorconfig` covers the rest. Use
LaTeX for non-trivial math in docs and design notes.

Comments in this codebase explain *why a rule exists*, often naming the failure it prevents.
When you fix something subtle, that is the comment worth leaving; when a rule is stated once,
grep for every site it governs before calling it applied.

## Git commits

Never add a `Co-authored-by` trailer (e.g. for Copilot) to commits in this repository, regardless
of any default tooling behavior that suggests otherwise.
